# Ascension — proposed decisions (awaiting owner approval)

`tasks/vnext/DECISIONS.md` holds owner-approved decisions only, so nothing below has been appended there. Each row is written in that file's voice and is ready to copy across once approved. Branch `ascension`, baseline `029eb51` (release 161).

| # | Decision | Status |
|---|---|---|
| D60 | **Programme edits carry a timestamp and the cloud merge keeps the newer copy.** The weekly plan (`settings.planUpdatedAt`), each dated override (`cutSupport.overrideMeta[date]`, kept as a tombstone when a day is cleared) and each saved routine (`cutSupport.templateMeta[gym__type]`) are stamped in `commit()` when the user edits them; `install()`, migrations and merges never stamp. On Login + Load the newer stamp wins; an unstamped copy loses to a stamped one; when neither is stamped, a factory value on this device (the A/B/C split or `DEFAULT_WEEKLY_PLAN` after D33; a routine equal to `TEMPLATES`/`NXT.defaults`; a goal range, start weight, TDEE, cardio target or name still at its default) counts as unset and the account's copy wins, with the goal range and its confirmation, and the start weight with its cut-start date, resolved as units. Two customised, unstamped copies keep this device's, as before. Saves read the account first and write nothing after a failed read; today's untouched queue is re-seeded from the routine the merge settled on (D22); waist rows union by id like other records; add-on lifts ride the cloud payload and backups; a full phone no longer stops `cut-support.js` at load. No new storage key, no record shape changed. Pinned by `wearables.plan-persistence.test.js` (25). Root causes in `tasks/ascension/reliability-report.md`. | Proposed |
| D61 | **Coaching Intelligence 2.0.** `coach.js` adds `NXT.coach`: one validated context shared by every coach; day statuses (`done / partial / missed / excused / moved / rest / today / upcoming / untracked`); a ranked, deduplicated insight list (≤3 on Today, one per domain, severity act / watch / info, each with evidence rows and a four-part Why: noticed, evidence, matters, can do); coordinator rules (staleness > 14 days dropped; a cautious weight decision demotes "move up" to a hold; catch-up outranks "week behind"; dismissed insights stay hidden until their evidence fingerprint changes); `trainAdvice()` that applies the same hold rule to Train's coach line without touching `coachFor()`/`aimFor()` (D25); and a deterministic last-week review. Rules only, no model calls, no score (D9). `review()`, `diagnose()`, `bestSet()`, `aimFor()`, `coachFor()` are called, not edited. Stored, additive, inside `settings.cutSupport`: `coach.dismissed`, `coach.reviewSeen`. Pinned by `wearables.coach.test.js` (48). | Proposed |
| D62 | **Day context and catch-up.** A missed lifting session is a fact the app can act on: a past planned lifting day with no working sets reads *Not logged*; the user can mark it *Excused* (sick, travel, rest, other; `cutSupport.dayNotes[date]`) from the day sheet, History or the coach; when today is not a lifting day and nothing is logged, Today and Train offer to move the most recent missed session to today, listing every consequence first (session moves, today's cardio dropped for the week, the missed day reads *Moved*, back-to-back lifting if so, the weekly plan unchanged) and writing only on confirmation through the existing `setDayType` path (so D60 stamping applies). Calendars show planned (session letter), not-logged, excused and moved days with a word for each; `liftsPlanned` excludes excused and moved days; a postponed workout is never counted as done. | Proposed |
| D63 | **Week in review.** Today shows the last completed Mon–Sun week once (until *Got it*): lifting days done of planned, sets and tonnage versus the week before, D20 outcomes (beat / matched / below), cardio minutes against the target, the morning average versus the week before (≥3 readings), excused and moved days, and next week's plan. All from `activityWeeks()`, `bestSet()` and the weekly-average rule already used by Week by week; nothing stored except `coach.reviewSeen`. | Proposed |
| D64 | **Exercise Details has a history chart.** Best working set per session for the same exercise at the same gym (`sessionRows` + `bestSet`), reps printed under each dot, the all-time best ringed and labelled, a gutter y-axis (D58), last 12 sessions by default with *All*, scrub and arrow keys with a stable readout carrying the D20 word, and the e1RM estimate behind an **off-by-default** `e1RM` toggle (I11): when off the Y domain is data-only (D2) with D51 headroom. States for 0, 1 and 2+ sessions. Performance rows open the same sheet for that lift and gym. Presentation only. | Proposed |
| D65 | **Launch lifecycle.** One launch colour `#07060B` (html style, `color-scheme`, `theme-color`, manifest, overlay). The branded overlay is the first painted frame and stays opaque until the hold (1.55 s from first visible frame) is met **and** the app has rendered; then one reveal (mark out 140 ms, backdrop 360 ms, shell settles 6 px over 420 ms, transform-only). No dimmed veil over the dashboard. Fallback 2.2 s, tap to skip, visibility/pagehide safety, reduced motion honours the OS and the in-app setting with a still frame. Pinned by `launch-verify.mjs` (83 checks). | Proposed |
| D66 | **Wearable modules are not loaded or precached.** The 13 `wearables.*.js` files stay in the repo with their suites, but the page no longer requests them and `sw.js` no longer shells them: they opened IndexedDB and re-rendered Home on every launch (painting the V99 layout first on a slow link), cost 353 KB and 13 requests, and hold no production data. Restoring the feature means re-adding the tags and the `VERSIONED` entries, not only flipping the D55 flag. Tesseract OCR loads on first use instead of at launch. | Proposed |
| D67 | **Service worker serves versioned assets stale-while-revalidate.** Files carrying this release's `?v=` (and the font and icons) are answered from the cache immediately and refreshed in the background; navigations stay network-first with the cached `index.html` as the offline fallback. A release bump still installs a new cache and deletes the old one. Pinned by `wearables.sw-strategy.test.js`. | Proposed |
| D68 | **One token set.** Legacy custom properties (`--bg`, `--panel*`, `--purple*`, `--nxt-*`, `--vn-*`, radius/font/motion names) resolve to the Strata values through an alias block in `strata.css`; the D44 field recipe (52 px, 14 px radius, 16 px text) wins inside every sheet; the legacy `.modal > .sheet` builders get the Strata sheet recipe; the last sky/cyan literals are gone (D54); dead rules removed from the older layers under a pixel-diff guard; touch targets ≥44 pt and text ≥11 px on the measured outliers. Details in `tasks/ascension/design-system-report.md`. | Proposed (pending that agent's report) |
